# Руководство по внесению вклада

Спасибо за ваш интерес к проекту! Мы рады любому вкладу.

## 🚀 Как внести вклад

### 1. Fork и Clone

```bash
# Fork репозитория через веб-интерфейс GitHub
# Затем клонируйте ваш fork:
git clone https://github.com/ВАШ_USERNAME/rectification-controller.git
cd rectification-controller
```

### 2. Создайте ветку

```bash
git checkout -b feature/ваша-фича
# или
git checkout -b fix/ваш-фикс
```

### 3. Внесите изменения

- Пишите понятный код
- Следуйте существующему стилю кодирования
- Комментируйте сложные участки
- Обновите документацию при необходимости

### 4. Тестирование

```bash
# Убедитесь, что код компилируется
pio run

# Запустите тесты
pio test
```

### 5. Commit

```bash
git add .
git commit -m "Описание изменений"
```

**Формат commit сообщений:**
- `feat:` - новая функция
- `fix:` - исправление бага
- `docs:` - изменения в документации
- `style:` - форматирование, точки с запятой и т.д.
- `refactor:` - рефакторинг кода
- `test:` - добавление тестов
- `chore:` - обновление зависимостей и т.д.

Примеры:
```
feat: добавлена поддержка MQTT
fix: исправлена утечка памяти в веб-сервере
docs: обновлена инструкция по установке
```

### 6. Push и Pull Request

```bash
git push origin feature/ваша-фича
```

Затем создайте Pull Request через веб-интерфейс GitHub.

## 🐛 Сообщения об ошибках

При создании issue включите:

1. **Описание проблемы** - что происходит
2. **Ожидаемое поведение** - что должно происходить
3. **Шаги воспроизведения** - как повторить проблему
4. **Окружение**:
   - Версия прошивки
   - Модель ESP32
   - Версия PlatformIO
   - Браузер (для веб-интерфейса)
5. **Логи** - из Serial Monitor
6. **Скриншоты** - если применимо

2. Дождитесь обсуждения

## 🧪 Тестирование

Обязательно протестируйте ваши изменения:

- ✅ Код компилируется без ошибок
- ✅ Код работает на реальном устройстве
- ✅ Веб-интерфейс работает корректно
- ✅ Система безопасности не нарушена
- ✅ Существующие функции не сломаны

## 📚 Документация

При добавлении новых функций обновите:

- README.md - если меняется API или использование
- Комментарии в коде
- Примеры использования
- Wiki (если необходимо)

- Код без комментариев
- Изменения без тестирования
- Нарушение безопасности
- Плагиат или использование закрытого кода
- Код, который ломает существующую функциональность
